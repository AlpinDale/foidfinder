foidfinder Privacy

FAQ & Troubleshooting

Common questions and error messages for foidfinder.net and the browser extension.

Errors

“This browser has no WebGPU, which foidfinder needs to run the model”

foidfinder runs the neural network locally on your GPU using WebGPU. Update to a supported browser:

  • Chrome / Edge: version 121 or newer.
  • Firefox: version 142 or newer (on platforms where WebGPU is enabled).
  • Safari: recent macOS / iOS versions with WebGPU enabled.

If you are self-hosting the web app, make sure it is served over HTTPS (or localhost); browsers disable WebGPU on plain HTTP.

“WebGPU is turned on, but the browser offers no GPU to it”

Your browser supports the WebGPU API, but could not obtain a hardware GPU adapter. Common causes:

  • Graphics acceleration is turned off. In Chrome/Edge, open chrome://settings/system, turn on Use graphics acceleration when available, and relaunch the browser.
  • Linux Chrome / Chromium. WebGPU/Vulkan is often disabled or blocklisted by default on Linux. Check chrome://gpu, update your Mesa/NVIDIA drivers, or enable chrome://flags/#enable-unsafe-webgpu.
  • Blocklisted GPU, outdated driver, or VM. Open chrome://gpu (Chrome/Edge) or about:support (Firefox) and check the WebGPU status and detected problems. Updating graphics drivers often fixes this; virtual machines and some Remote Desktop sessions do not expose a WebGPU-capable GPU.

“This GPU or browser lacks 16-bit floats in WebGPU shaders (shader-f16)”

The model requires the WebGPU shader-f16 feature for memory and speed. Very old GPUs (for example pre-Turing NVIDIA cards or older integrated Intel GPUs), outdated drivers, or software renderers (like SwiftShader) do not expose shader-f16. Updating your graphics drivers may enable it on supported hardware; otherwise that GPU cannot run the in-browser model.

“GPU device lost” / “The in-browser engine failed to start” / “The model did not answer”

The browser reset or terminated the GPU worker—usually because of a graphics driver reset, system sleep/wake, low GPU memory, or the browser suspending a background process. Click Retry (or right-click the image again in the extension). If it repeats, close GPU-heavy tabs or games and reload the page.

“The model download failed / timed out / stalled / was incomplete”

On first use, foidfinder downloads the 178 MB model checkpoint from Hugging Face (huggingface.co and *.hf.co) and caches it in your browser.

  • Check that no firewall, VPN, or content blocker is blocking huggingface.co or *.hf.co.
  • Make sure you have at least ~250 MB of free disk space for browser storage.
  • If your connection dropped mid-download, click Retry (or try again in the extension).

Extension: “The image could not be downloaded / read” or “server refused it / sent a page”

By default the extension only uses activeTab permission, so it cannot directly fetch images hosted on a different domain unless that host allows cross-origin reads, and sites with hotlink protection (such as pixiv) reject requests without the page's referrer.

  • Click Allow full-quality downloads from all sites on the card (or open the extension's settings) to grant optional all-sites access. foidfinder still only runs when you click its menu item and never uploads images.
  • Images inside cross-origin <iframe>s or browser-restricted pages (such as the Chrome Web Store or chrome:// / about: pages) cannot be read by extensions; save the image and drop it on foidfinder.net instead.

“Larger than 32 MB / 64 megapixels / ... pixels” or “Unsupported or damaged image”

foidfinder accepts JPEG, PNG, WebP, GIF, AVIF, and BMP files up to 32 MB, 64 megapixels, and your GPU's maximum 2D texture dimension (usually 8192 or 16384 pixels per side). Convert unsupported formats (such as HEIC, TIFF, or PSD) or downscale very large images before identifying.

General

Do my images leave my computer?

No. Everything runs locally in your browser via WebGPU. The only network request the web app makes is the one-time model download from Hugging Face. See the Privacy Policy for details.

Why does the first identification take longer?

The first run downloads the 178 MB model once and stores it in your browser's Cache API (separate caches for the website and the extension). Later runs load from local storage in about a second.

Firefox extension note: Firefox suspends idle MV3 extensions after about 30 seconds, which releases GPU memory and requires recompiling shaders next time. If you identify images frequently, open about:addons → Extensions → foidfinder → Options (or Preferences) and enable Keep model loaded.

Why did the extension say “from a screenshot of the page”?

When the extension cannot download the original image file (because all-sites access is off or the host blocks direct reads), it falls back to cropping the image from a screenshot of the visible tab. That uses the displayed size on screen, which can reduce accuracy for small thumbnails. Turning on Allow full-quality downloads from all sites in the extension settings lets it fetch the original file.

Why wasn't a character, series, or artist recognized?

foidfinder currently uses Haruka Tagger (98,782 Danbooru tags, including 38,447 artists). Characters or artists introduced after the model's training cutoff, heavy crops, strong filters, or low-resolution screenshot fallbacks can score below the display threshold. Check the Possible entries for below-threshold guesses.

How do I delete the cached model?

Clear site data for foidfinder.net in your browser settings to remove the website's copy, or remove the extension to delete the extension's copy.

Report bugs or ask questions on github.com/AlpinDale/foidfinder/issues. Include your browser version, OS, and the WebGPU section from chrome://gpu (or about:support on Firefox).
